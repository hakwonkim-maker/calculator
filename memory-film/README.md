# MEMORIA 기념영상 스튜디오

사진 폴더만 선택하면 **인트로 → 사진(자연스러운 전환·카메라 움직임·자막) → 엔딩**으로 이어지는
영상을 만들어 **PC에 MP4 파일로 저장**하는 설치형 프로그램입니다.
창립기념식에서 시작해 웨딩·생일·졸업·여행·가족·추모·행사·연말결산 영상까지 만들 수 있습니다.

### v1.5 변경 사항 — 음악 박자 맞춤 · 옛 사진 복원
- **음악 박자에 맞춘 장면 전환**: 음악을 넣으면 박자(BPM)를 자동 분석해, 사진이 바뀌는 순간을 박자에 맞춤 (마디 첫 박 등 센 박 우선).
  전체 길이는 그대로, 인트로 글자·장면 최소 길이 보장. 음악 단계에서 켜고 끄기, 곡별 BPM 표시. 분석은 별도 스레드(3분 곡 약 0.5초)
- **옛 사진 자동 보정**: 누렇게 변한 인화 사진·바랜 색·흐린 대비·빠진 채도를 자동 복원 (채널별 레벨·화이트밸런스·감마·채도).
  기본은 ‘옛 사진만’ — 바래거나 색이 틀어진 사진만 골라 보정하고 정상 사진은 그대로. 사진별 자동/보정하기/원본, 누르고 있으면 보정 전 비교.
  원본 파일은 바뀌지 않음
- 버그 수정: 몽타주·인트로용 사진 캐시 키 오류(개발 중 발견, 배포 전 수정)

### v1.4 변경 사항 — 지루하지 않은 영상 · 무료 음악
- **새로 만들기** 버튼(Ctrl+N): 저장하지 않은 작업이 있으면 *저장하고 새로 만들기 / 저장 안 함 / 취소* 확인
- **몽타주 장면 자동 배치**: 사진 사이사이에 모자이크 그리드·폴라로이드·분할 패널·필름 스트립 장면을 골고루 섞어 넣음
  (빈도 끄기/가끔/보통/자주, 자막·개별 설정이 있는 사진과 ‘몽타주에서 빼기’한 사진은 한 장씩 크게)
- **임팩트 인트로 2종**: *타임 롤*(흑백 사진이 세로로 휘리릭 흐르며 연도가 30년을 거슬러 오름 → 섬광과 함께 컬러 전환 + 타이틀),
  *플래시 컷*(사진이 번쩍이며 빠르게 교차, 큰 글자가 꽂힘)
- **인트로 세부 조정**: 글자 전에 사진만 보이는 시간, 글자 나타나는 속도(천천히/보통/빠르게), 글자 뒤 사진 어둡기,
  ★ 대표 사진을 인트로·엔딩에 먼저 사용
- **무료 음악 30곡**: 퍼블릭 도메인 클래식 연주(Wikimedia Commons, 출처 표기 불필요) + Kevin MacLeod 곡(incompetech.com, CC BY 4.0 — 쓰면 영상 끝에 출처 한 줄 자동 삽입).
  분위기별(따뜻·감동/잔잔·서정/밝고 경쾌/웅장·벅참/신나는/유쾌·발랄) 미리 듣기 → 클릭 한 번으로 넣기, 음량 평준화, 영상보다 짧으면 자동 반복.
  설치 파일 빌드 시 받아 포함하며, 빠진 곡은 프로그램에서 인터넷으로 받기. (처음 쓰려던 FreePD.com은 폐쇄되어 교체)
- **자동 사진 선별**: 폴더째 불러온 뒤 목표 길이(예: 3분)와 1장당 시간(2~5초)만 고르면 좋은 사진만 골라 배치
  (★·자막 사진 유지, 연사 중복 제거, 폴더·연도별 균형, 선명도·노출 분석). 빠진 사진은 삭제하지 않고 ‘제외’로 표시, 언제든 해제.
  사진이 많으면 불러오자마자 *3분 영상으로 좋은 사진만 고르기* 1클릭 제안
- **촬영일순 정렬 개선 (버그 수정)**: 촬영 정보(EXIF)가 없는 스캔·메신저 사진이 파일 날짜(스캔·복사한 날)로 정렬돼
  1999년 사진이 2003년 사진 뒤에 나오던 문제 수정 → 파일 이름의 날짜(`KakaoTalk_19990512…`)·폴더 이름의 연도(`1999_창립식`)를 함께 사용,
  EXIF ‘수정한 날짜’는 촬영일로 쓰지 않음, 카메라 일련번호(`IMG_2010.jpg`)는 연도로 오인하지 않음. 기존 프로젝트는 *촬영일순* 클릭 시 자동 보정
- **폴더 이름 표시**: 사진이 들어 있던 폴더 이름(예: 2019 체육대회)을 왼쪽 위에 작게 — 표시 안 함 / 폴더가 바뀔 때만 / 모든 사진

### v1.3 변경 사항 — 제작 속도 · 사용 편의
- **제작 속도 1.7배** (같은 영상·같은 PC 실측 204.8초 → 122.1초, GPU 없는 환경 기준)
  - 제목·입자 장면의 화면 전체 블러 제거 → 장면당 약 2,000ms → 110~230ms (10배 이상)
  - GPU에서 바로 YUV420 변환 + 비동기 읽기(PBO) → 전송량 62% 감소, FFmpeg 색변환 생략 (화질 동일, PSNR 비교 검증)
  - 그래픽카드 인코더 자동 사용 (NVIDIA·Intel·AMD), 실패 시 CPU로 자동 재시도
  - CPU 인코딩 프리셋 최적화 (실측: 같은 화질·용량에서 58% 빠름), 쓰는 전환 효과만 컴파일, 필요할 때만 밉맵, 사진을 디코딩 단계에서 바로 축소
- **편의 기능**: 예상 제작 시간 표시(이 PC에서 측정), **빠른 시안 만들기**(720p), 저장 공간 부족 사전 경고,
  작업 표시줄 진행률·완료 알림, 단계별 ‘다음’ 버튼, 문구 입력 시 미리보기가 해당 장면으로 이동,
  음악 추가 시 ‘영상 길이를 음악에 맞추기’ 제안, 마우스 휠로 필름스트립 이동, 필름스트립 ‘작게’ 보기, 현재 장면 표시(사진 12 / 220)

### v1.2 변경 사항
- **전체 영상 길이 설정**: 분·초 입력 또는 1·2·3·5·10·15분/음악 길이 클릭 → 사진 1장당 시간 자동 계산, 사진을 추가해도 길이 유지.
  사진이 많으면 전환도 자동으로 짧아지고, 불가능한 길이는 가능한 최소 길이를 안내
- **사진 200장 이상**: 보이는 썸네일만 생성(지연 로딩), 썸네일 축소 디코딩, 카드별 갱신으로 재렌더 최소화,
  가져올 때 해상도를 파일 헤더에서 바로 읽음 — 360장 가져오기·스크롤·재생, 1080p 전체 렌더 시 메모리 일정(약 85MB) 확인
- **버그 수정(2차 검토)**: 크레딧 글자가 대체 글꼴로 나오던 문제, 지정한 중심점이 이동 중 화면 밖으로 나가던 문제,
  기본 구도가 아래로 치우치던 문제, 썸네일 캐시 무제한 증가, GPU 리셋 시 검은 썸네일 고착,
  블라인드 전환 끝의 잔상, 템플릿 재선택 시 이름 유지, 세로 촬영 사진의 가로세로 판정, 특정 셰이더 실패 시 전체 내보내기 중단,
  긴 크레딧이 너무 빨리 지나가던 문제, 사진이 매우 짧을 때 실제 간격이 표시값과 다르던 문제

## 1. 빠른 시작

### 설치 파일 받기 (권장) — 추가로 설치할 프로그램 없음
GitHub → **Actions → "MEMORIA Windows Installer"** → 최신 실행의 Artifacts에서
`MEMORIA-Film-Studio-Setup-x.y.z.exe` 다운로드 → 설치. 자세한 내용은 [설치 가이드](docs/설치가이드.md).
Windows에서 직접 만들려면 [Node.js 22 LTS](https://nodejs.org/ko/download) 설치 후 `build-installer.bat` 더블클릭.

### 직접 빌드
```bash
cd memory-film
npm install
npm run start        # 앱 실행 (빌드 후 Electron 실행)
npm run dist:win     # Windows 설치 파일 → release/*.exe  (Windows에서 실행)
npm run dist:mac     # macOS dmg (Mac에서 실행)
```
개발 모드: 터미널 1 `npm run dev`, 터미널 2 `npm run electron:dev` (수정 즉시 반영).

### 사용 흐름 (5단계)
| 단계 | 하는 일 |
|---|---|
| ① 사진 | 폴더 선택(하위 폴더 포함) → 촬영일순 자동 정렬. 연도별 챕터 카드·연도 라벨 자동 생성 |
| ② 문구 | 인트로 스타일 선택, "30 / ANNIVERSARY / 함께 걸어온 30년 / 1996—2026 / 회사명", 로고, 엔딩 감사 문구 |
| ③ 스타일 | 컬러 테마 4종, 타이포그래피 4종, 전환 스타일(우아/시네마틱/경쾌), 카메라 움직임, 사진 색감 |
| ④ 음악 | 여러 곡 크로스페이드, 반복, 페이드인/아웃, **음악 길이에 영상 자동 맞추기** |
| ⑤ 내보내기 | 점검 체크리스트 → 1080p/4K, 30/60fps → MP4 생성 |

단축키: `Space` 재생 · `←/→` 장면 이동 · `Delete` 삭제 · `Ctrl+Z / Ctrl+Shift+Z` 실행취소/재실행 · `Ctrl+S` 저장 · `Ctrl+A` 전체 선택

### 사진 장면
- **켄 번스 모션**: 확대/축소/좌우/상하 패닝을 시드 기반으로 섞되 같은 움직임이 연속되지 않게 배치. 인물 얼굴이 주로 있는 화면 위쪽으로 살짝 치우친 구도.
- **화면 맞춤(자동)**: 16:9·3:2 사진은 꽉 채우고, 4:3·세로·정사각 사진은 잘리지 않도록 **같은 사진의 흐린 배경 + 그림자 있는 원본**으로 표시 (단체사진 머리 잘림 방지). 옵션: 인화지 흰 테두리.
- **자막**: 금색 연도 라벨 + 설명 문구가 글자 단위로 등장, 하단 그라데이션으로 가독성 확보.
- **챕터 카드**: "1996 · 작은 시작" 같은 구간 제목. 다음 사진을 흐리게 깐 배경 위에 표시.
- **엔딩**: 사진 갤러리 월이 천천히 흐르는 위로 감사 메시지 → 회사명/로고 → 블랙 페이드아웃(진행자가 정지할 여유).

디졸브 · 블러 디졸브 · 빛 번짐 · 라이트 릭 · 모프 · 소프트 와이프 · 아이리스 · 블랙 페이드 · 화이트 플래시 · 줌 블러 · 패럴랙스 슬라이드 · 크로스 워프 · 물결 · 소용돌이

**핵심 설계 원칙**
1. **결정적 렌더링** — 모든 프레임은 `시간 t`의 순수 함수(랜덤도 시드 기반). 그래서 미리보기와 최종 영상이 프레임 단위로 같고, 어느 지점이든 즉시 탐색 가능.
2. **해상도 독립 디자인** — 1080p 기준 단위(`u = H/1080`)로 디자인 → 720p 미리보기, 4K 출력 모두 같은 레이아웃.
3. **메모리 안전** — 2천만 화소 원본을 그대로 쓰지 않고 출력 해상도×1.35로 줄여 보관, 최근 장면만 캐시. 사진 수백 장도 안정적.
4. **표준 출력** — H.264 High / yuv420p / BT.709 / faststart MP4 + AAC 256k. 행사장 PC, PowerPoint, 프로젝터 플레이어 어디서나 재생.

### 프로젝트 파일
`.memoria` (JSON). 사진은 원본 경로를 참조합니다. 사진 폴더를 옮기면 "파일 없음"으로 표시됩니다.
작업 내용은 자동 저장되어 프로그램이 갑자기 꺼져도 다음 실행 시 복원됩니다.

## 5. 테스트

```bash
npm run fixtures                         # 다양한 비율의 샘플 사진·음악 생성 (ffmpeg 필요)
PW_PATH=<playwright 경로> npm run test:render -- golden   # 지정 시간 프레임을 tests/out 에 이미지로 저장 (golden|mosaic|light|royal)
PW_PATH=<playwright 경로> npm run test:ui                 # UI 각 단계 스크린샷
PW_PATH=<playwright 경로> xvfb-run -a npm run test:e2e    # 실제 Electron 앱: 폴더 가져오기→자막→음악→720p 내보내기
```
- `xvfb-run -a node tests/persona-sim.mjs <A|B|C> <사진폴더>` : 가상 사용자 3명(초보·꼼꼼·옛 사진)이 실제 앱을 클릭해 영상까지 만드는 시뮬레이션 (클릭 수·시간·오류 기록)
- `node tests/beats-test.mjs` : 박자 분석(72~150 BPM 합성 음원, 위치 오차 4ms) + 전환 박자 맞춤 단위 테스트
- `node tests/enhance-test.mjs` : 옛 사진 복원(바램·변색 합성 사진 → 원본과의 차이 약 60% 감소, 정상 사진은 그대로) 단위 테스트
- `node tests/photodate-test.cjs` : 사진 날짜 추정(EXIF·파일 이름·폴더 이름) 단위 테스트
- `MF_COMMONS_API=<모의 Commons API> MF_INCOMPETECH=<모의 서버>`를 주면 E2E에서 무료 음악 목록 받기 → 내려받기 → 넣기까지 검증합니다.
- `node scripts/fetch-music.cjs` : 무료 음악 30곡을 `music-library/`에 준비 (설치 파일 빌드 시 자동 실행, 실패해도 빌드는 계속)

E2E는 개발 실행과 패키징된 앱(`MF_EXE=release/linux-unpacked/memoria-film-studio`) 모두에서 통과했으며,
결과 MP4(H.264 yuv420p BT.709 30fps + AAC)를 ffprobe와 프레임 추출로 검증했습니다.
